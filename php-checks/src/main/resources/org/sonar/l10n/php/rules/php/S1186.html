Why is this an issue?

An empty function is generally considered bad practice and can lead to confusion, readability, and maintenance issues. Empty functions bring no functionality and are misleading to others as they might think the function implementation fulfills a specific and identified requirement.

There are several reasons for a function not to have a body:

  • It is an unintentional omission, and should be fixed to prevent an unexpected behavior in production.
  • It is not yet, or never will be, supported. In this case an exception should be thrown.
  • The method is an intentionally-blank override. In this case a nested comment should explain the reason for the blank override.

Exceptions

This rule doesn’t raise an issue in the following cases:

  • Empty methods in abstract classes: They can provide optional hooks for subclasses.
  • Constructors with promoted properties: The constructor is needed to initialize the promoted properties, even when its body is empty.
  • Parameterless private constructors: They prevent direct instantiation of classes that expose only static methods, such as utility or factory classes.
  • Empty functions and methods in PHP API stub files: They declare an API without providing an implementation. This includes files ending in .stub.php and files with a leading PHPDoc @generate-function-entries or @generate-class-entries tag, as described in the PHP stub guide.
abstract class Animal {
  public function speak() {}  // default implementation ignored
}

class Person {
  public function __construct(private string $name) {}  // constructor with promoted property ignored
}

class Utility {
  private function __construct() {}  // private constructor without parameters ignored
}

How to fix it

Code examples

Noncompliant code example

public function shouldNotBeEmpty() {  // Noncompliant - method is empty
}

public function notImplemented() {  // Noncompliant - method is empty
}

public function emptyOnPurpose() {  // Noncompliant - method is empty
}

Compliant solution

public function shouldNotBeEmpty() {
  doSomething();
}

public function notImplemented() {
  throw new Exception('notImplemented() cannot be performed because ...');
}

public function emptyOnPurpose() {
  // comment explaining why the method is empty
}
